DialogMenu RGBA 0.1.5 · Java 25 · Minecraft 26.3 · 资源包格式 97.1 起

什么是 RGBA 版

这是 DialogMenu 的独立着色器版本。它复用整字字库，在颜色数据中编码文字偏移和图片尺寸，再由核心文字着色器解码，减少按不同纵向位置重复准备字体的开销。

普通玩家不需要客户端 Mod，但必须接受匹配的资源包。点击仍由原版 Dialog 与服务端会话校验处理，不是任意客户端鼠标事件接口。

YAML 与源图片→校验、字库与资源包→客户端接收→Dialog 与 Shader

先读哪一篇

  • 首次安装：运行环境 → 可下载的完整示例。
  • 想减小资源包：字库与颜色 → 共享图片拉伸 → 什么时候需要发新包。
  • 接入自己的业务：外部变量 → 集合与表单 → 完整 Java 示例。
两个独立项目原 palkane/DialogMenu 保留以前公开的原生版本；本 Wiki 仅对应 palkane/DialogMenu-RGBA。两者共用插件名、命令、API 和数据目录，只能安装一个。

不包含什么

随包只有 layout-demo、layout-detail 两个公开示例，没有服务器业务、经济系统或整套菜单。静态图片不是任意 ItemStack 的 3D 模型；没有右键、Shift、中键或服务端滚轮回调。可视化编辑需要另配匹配的编辑客户端，普通玩家显示菜单不需要它。

安装与版本切换

运行环境

  • Java 25，提供 26.3 Dialog API 的 Paper 系服务端，以及 Minecraft 26.3 客户端。
  • 客户端接受菜单资源包；核心文字 Shader 不能被其他包不兼容地覆盖。
  • 最低资源包格式为 97.1，不是旧版 Spigot 通用插件。

CraftEngine、PlaceholderAPI、Skript 都是可选集成。只有布局实际使用其资源、变量或集合协议时才需要安装；静态入门示例不依赖它们。

从源码构建

本 Wiki 以仓库的 0.1.5 源码为基线，不假定已有可下载的 Release。使用 Java 25，在仓库根目录执行：

终端 · Windows 使用 gradlew.bat
./gradlew build

产物为 build/libs/DialogMenu-rgba-0.1.5.jar。Gradle 会运行布局、渲染、绑定与表单检查；构建通过不代表你的客户端组合已通过验收。

安装步骤

  1. 备份原 JAR 及 plugins/DialogMenu/。正常停止服务器，只保留一份 DialogMenu JAR，然后启动。
  2. 管理员执行 /dialogmenu status，应包含 renderer=rgba；等待布局资源准备完成。
  3. 按资源包流程生成、分发并接收资源。
  4. 玩家执行 /dialogmenu open layout-demo，验证详情跳转、返回和关闭。

从原生版切换

保留原 plugins/DialogMenu 中的布局、图片和玩家偏好，先迁移旧 backend，再正常停服换 JAR。重新生成并接收匹配的资源包。不能靠 reload 换插件版本。

不是配置开关shader-rendering 和 -Ddialogmenu.rgba 旧开关不再选择发行版。当前渲染器由 JAR 内的发行标记固定。不要同时放入原生和 RGBA 两个包。

第一份菜单

新建 plugins/DialogMenu/layouts/hello.yml。文件名与 id 一致；ID 使用小写字母、数字、-、_，首字符必须是字母或数字，最长 64 字符。

hello.yml · 完整示例
schema-version: 1
id: hello
canvas: {width: 300, height: 180}
events:
  open: 'sound: UI_BUTTON_CLICK-0.5-1'
frontend:
  panel:
    type: rectangle
    width: 300
    height: 180
    color: '#EEF2F7'
  title:
    type: text
    content: '你好，{player}'
    color: '#243247'
    size: 8
    offset: {y: 48, z: 1}
  button-bg:
    type: rectangle
    width: 140
    height: 28
    color: '#D9E5F7'
    offset: {y: -12}
  button:
    type: text
    content: 点击打招呼
    color: '#243247'
    offset: {y: -12, z: 1}
    clickable: true
    tooltip: 向自己发送消息
    actions:
      all: 'sound: UI_BUTTON_CLICK-0.5-1'
      left: 'tell: 你好，{player}！'
  close:
    type: text
    content: '×'
    color: '#243247'
    offset: {x: 132, y: 72, z: 2}
    actions: close

加载与打开

  1. 保存文件，管理员执行 /dialogmenu reload，等待成功提示。
  2. 完成资源包更新，让客户端接收新包。仅改 YAML 不等于客户端已拿到字库。
  3. 玩家执行 /dialogmenu open hello small。
  4. 点击文字“点击打招呼”，应听到声音并收到问候；点击“×”关闭。
点击跟随文字，不跟随背景矩形只是底色，不是独立按钮区域。本例文字带动作，矩形边缘不应执行它。要做整块可点击按钮，可使用带动作的 image。

Esc 默认禁用，应保留可见关闭入口。界面不是整张文字截图：背景和文字始终是不同元素。

命令与配置

命令

命令用途
/dialogmenu打开 default-layout。
/dialogmenu open [id] [small|medium|large]打开页面；档位宽度分别为 300 / 360 / 420，也接受“小 / 中 / 大”。省略档位使用配置宽度。
/dialogmenu list列出已加载的页面 ID；模板列出其各 page ID。
/dialogmenu close关闭自己的菜单并清理会话。
/dialogmenu reload重新读取配置、布局和资源，在后台准备新快照。
/dialogmenu resources导出当前快照资源，不重读 YAML，也不自动给客户端发包。
/dialogmenu status查看布局数、活动视图数和 renderer=rgba，不是客户端渲染回执。
/dialogmenu textscale [倍率]查询或设置文字倍率；必须是配置中的选项，可带 x 后缀。
/dialogmenu scale [0.75|1]查询或设置画布倍率，与文字倍率不是同一偏好。
/dialogmenu edit [menu]管理员编辑入口，需匹配的独立编辑客户端 Mod。

open / close / textscale / scale / edit 需要玩家执行。reload / resources / status / edit 需要 dialogmenu.admin；基础命令权限为 dialogmenu.use，菜单和元素还可声明自己的权限。

config.yml

config.yml · 配置文件，不放入 layouts/
default-layout: layout-demo
canvas-width: 300
max-canvas-pixels: 131072
close-with-escape: false
text-scales: [1, 1.5, 2]
default-text-scale: 1
craftengine-auto-reload: true
craftengine-resources: ../CraftEngine/resources
  • canvas-width：64..512。实际画布还受高度、面积限制。
  • max-canvas-pixels：4096..524288，默认 131072；增大不取消实际宽高限制。
  • close-with-escape：可由单页同名字段覆盖。需要明确清理业务时，优先提供关闭动作。
  • text-scales：准备的文字倍率列表；增多可能增加字库资源与准备时间。
  • craftengine-resources：CE 源资源查找目录，不是客户端 ZIP 的下载地址。

玩家文字、画布偏好保存在 player-text-scales.yml 的不同字段中。配置不适配新倍率时，应先修布局，而不是期待插件自动重排。

坐标、尺寸与图层

中心原点

画布中心是 (0, 0)。X 正方向向右，Y 正方向向上。offset.z 越大越靠前；图片与文字共享图层顺序。组内坐标叠加父组偏移和缩放。

逻辑坐标示意，不是 Minecraft 客户端截图。

300 × 180 · 比例 1.0

逻辑尺寸与显示尺寸

canvas.width/height 定义布局坐标系。打开时指定的宽度决定比例，显示高度按原比例计算，再乘玩家画布倍率。例如 300×180 的布局，以 420 宽打开时是 420×252；选择 scale 0.75 后约为 315×189。

YAML 逻辑宽高解析范围为 16..4096，但实际显示宽必须在 64..512、高不超过 1024、面积不超过 max-canvas-pixels。逻辑参数能解析，不代表任意显示尺寸都能使用。

缩放和旋转

  • offset: {x, y, z}，默认均为 0。
  • scale: {x, y, z}，默认均为 1，X/Y 必须大于 0，Z 只能为 1。
  • rotation: {x, y, z}，只支持平面 Z 旋转；文字、group 不支持旋转。
  • scale-text-with-canvas 默认 false；文字还受字号、玩家 textscale 和字体约束，不要假定它随背景任意缩放。
布局不会自动响应式重排不同宽度、文字倍率可能造成越界、换行增加或点击范围变化。发布前要实际打开各目标组合。

画面元素

所有元素写在 frontend，键名遵循布局 ID 规则。元素可嵌套在 group.children 中。

类型与字段

type主要字段说明
groupchildren、offset、scale只组织子元素，不产生自己的图形或点击区。
rectanglewidth、height、color、opacity实心矩形。
framewidth、height、thickness、color边框，thickness 默认 1。
linewidth、thickness、color线条高度取 thickness。
textcontent、size、color、alignment、line-width、max-lines独立文字，可带动作与提示。
imagesource、width、height、reuse-texture源图片或纹理引用，可带动作与提示。

平面图形默认宽高 16；文字默认字号 8。color 为引号包住的 '#RRGGBB'，默认白色；opacity 为 0..255，默认 255。图片的保色路径不把 color 当作通用染色器。

分组示例

下面是节点片段，不是独立文件。它把标题与横线一起移动。group 不能直接挂点击动作。

frontend 内的片段
header:
  type: group
  offset: {y: 55, z: 1}
  children:
    title:
      type: text
      content: 我的菜单
      color: '#243247'
    rule:
      type: line
      width: 240
      color: '#CBD5E1'
      offset: {y: -18}

显示与权限

visible: false 静态隐藏。动态 visible-if 只在多页模板中处理。菜单顶层 permission 控制打开权限；文字/图片上的 permission 控制其交互授权，不代替业务插件的交易和数据校验。

没有独立 backend，也没有通用三维 model 元素。未知字段会报错，不会悄悄当作新功能。

文字、字库与换行

整字共享

RGBA 按字号等实际字体需求共享整字资源，不为每个 Y 偏移复制一份汉字 PNG。自动准备 3500 个唯一常用汉字，以及布局所需字符；这不是完整 Unicode，也不保证所有生僻字、符号或 Emoji 都有字形。

统一字号、少量颜色、少量玩家倍率通常比大量字号和颜色更省。不是“所有文字固定 9px”：size 默认 8；9px 是原生 plain_message 的行步长，二者不要混用。

换行示例

text-demo.yml · 完整示例
schema-version: 1
id: text-demo
canvas: {width: 300, height: 180}
frontend:
  paragraph:
    type: text
    content: '这是一段独立文字，超过设置的行宽后换行。'
    size: 8
    color: '#243247'
    alignment: left
    line-width: 200
    max-lines: 4
    offset: {x: -100, y: 38}
  close:
    type: text
    content: 关闭
    color: '#243247'
    offset: {y: -60}
    actions: close

line-width 是布局中的文字行宽，不是字符数量；必须与 max-lines 成对配置，后者为 1..32。超出准备或行数限制会失败，不会默默吞字。alignment 可为 left / center / right，默认 center。

颜色与格式

支持 & 与 § 的 legacy 颜色、RGB 和粗体。RGBA 文字明确拒绝斜体、下划线、删除线和随机样式。不要用这些装饰去制作命中区域。

准备颜色表最多 256 项；颜色由正常的 color 或文字格式配置，不需要手工填写编码 RGB。动态输出的新颜色也要提前准备。

补充字符

动态内容中的罕用字可用模板顶层 characters 补充，并通过 preview / fallback / values / samples 准备可能的输出。普通单页顶层不接受 characters，即使只需一页，也应改用 pages 模板。

准备新字符、字号、倍率或颜色后，需要重载、检查新资源并让客户端接收更新。动态运行时字符串不等于自动生成一份完整字体。

字号边界

配置解析接受 1..128，但实际字体 ascent、原生命中与画布还有限制；极小字号可能被拒绝，不能把解析范围当作全部可用。建议从默认 8 和现有 textscale 组合开始。

图片与宽高拉伸

源图与显示宽高

自有 PNG 放在 plugins/DialogMenu/images/，source 写相对路径。加载器要求源图宽高为 16 的整数倍，且各在 16..256。禁止越出 images 目录的路径。

符合条件的自有图会生成一个共享 wrapper，由 Shader 独立改变显示宽和高，不必为每一种尺寸复制 PNG。协议尺寸为 1..512，但仍受画布、裁切、命中与原生字体限制，不代表所有尺寸位置都一定可显示。

拉伸示例

先下载下面的 16×16 示例源图，放入 images/demo-panel.png，再保存布局。该示例图仅用于验证非等比拉伸。

下载 demo-panel.png

image-demo.yml · 完整示例
schema-version: 1
id: image-demo
canvas: {width: 300, height: 180}
frontend:
  panel:
    type: image
    source: demo-panel.png
    width: 143
    height: 37
    offset: {y: 12}
    tooltip: 同一源图，独立宽高
    actions: 'tell: 点击了拉伸图片'
  label:
    type: text
    content: 图片独立拉伸
    color: '#243247'

  close:
    type: text
    content: 关闭
    color: '#243247'
    offset: {y: -65}

走 Shader 的条件

  • 自有源图、无旋转、节点 opacity: 255，完整位于画布内，不被裁切。
  • 源图各边不超过 254；结合 16 倍数的加载规则，当前可用到 240×240。256×256 源图仍可加载，但不走这条 wrapper 路径。
  • 实际请求显示宽高各不超过 512。PNG 自身含透明像素不等于设置了节点 opacity。

不符合 wrapper 条件的自有图会使用已有渲染路径，可能准备不同的图形资源；不要据此承诺所有旋转、透明或裁切变化都不用新包。拉伸是最近邻采样，不是九宫格，边框也会随之变形。

原版与 CraftEngine 纹理

source来源
minecraft:item/book内置支持的原版平面纹理，不是任意模型渲染。
craftengine:image/namespace:id已注册 CE 图片；icon 前缀也是图片入口。
craftengine:item/namespace:id可解析的 CE 物品纹理，不自动渲染其复杂模型。
craftengine:texture/namespace:item/pathCE 资源目录中的原纹理。

reuse-texture: true 仅用于 image，选择可复用的 CE 原纹理；CE 图集引用会自动使用直引路径。原版与这些直引资源必须等比、无旋转、无裁切、opacity=255，不能照上面的自有 PNG 示例非等比拉伸。直引只输出 provider，客户端需要原版或 CE 资源本身。

点击、悬停与双击

动作写在元素上

只有 text 和 image 可配置 clickable / actions / tooltip / permission。命中随实际字形、分行、图层与倍率变化，不另配矩形坐标。

clickable 默认 true；设为 false 不执行回调，但可以保留 tooltip 和动作配置。tooltip 接受字符串或字符串列表。可见底色不自动扩大文字的点击范围。

即时点击与手势仲裁

  • actions: 'tell: ...' 或字符串列表：即时执行。
  • actions.all 和 actions.left：依次即时执行，不是右键入口。
  • actions.single 和 actions.double：同一个控件进行 300ms 仲裁；配置 double 后，单击等待窗口结束。
  • single/double 不能与 all/left 混用。
gesture.yml · 完整示例
schema-version: 1
id: gesture
canvas: {width: 300, height: 180}
frontend:
  target:
    type: text
    content: 单击查看，双击确认
    color: '#243247'
    tooltip: 双击窗口为三百毫秒
    actions:
      single: 'tell: 单击'
      double: 'tell: 双击'
  close:
    type: text
    content: 关闭
    color: '#243247'
    offset: {y: -60}
    actions: close

服务端边界

点击会校验当前会话、控件、权限与动作。页面替换、关闭、重载后的旧点击不能继续操作新页面。回调仍只说明一个配置动作被触发；扣款、购买、SQL、库存和防重复提交由业务端校验。

原版 Dialog 的整体滚动不等于插件收到滚轮事件。不要配置 right、shift、wheel 等未支持动作分支。

动作与事件

动作格式通常为 '类型: 参数'；无参数动作直接写名称。多个动作按字符串列表配置。命令参数不需要前导 /。

动作表

动作用途与注意
tell: 文本向当前玩家发送消息。
sound: UI_BUTTON_CLICK-0.5-1声音 name-volume-pitch；音量 0..16、音高 0..2，也可用命名空间声音 ID。
command: spawn先关闭菜单，再由玩家执行命令。
command-in-place: balance不预先关闭菜单，按玩家身份执行。
console: ...先关闭，再执行控制台命令；只能由可信管理员维护，不能交给不可信用户编辑。
open: page-id打开已加载页面；不存在的目标在加载时被拒绝。
back返回导航历史中的页面；无历史时关闭。
close关闭当前菜单并清理会话。
return立即结束当前动作列表，不关闭菜单，也不等于 back。
toggle: editing切换已声明的模板 state 布尔值。
set: page 2更新已声明的模板 state。
notice: 文本设置模板 notice 状态供展示。
entry: collection-id item-id模板集合条目操作；external 集合回传稳定 ID，不是任意物品发放命令。
callback: inspect向当前 Java binding 回传字符串，由业务插件处理。

打开与关闭事件

events.open 和 events.close 只允许 tell、sound，防止导航递归。不能在关闭事件中再 open 页面或执行业务命令。

单页或 pages 内的事件片段
events:
  open:
    - 'sound: UI_BUTTON_CLICK-0.5-1'
  close:
    - 'tell: 已关闭菜单'

命令与回调如何选择

已有独立命令可以直接用 command。需要绑定会话、业务数据和稳定 ID 时，使用 callback 或 external collection 的 Java 回调。不要在 YAML 中重造一套交易数据库。

多页、变量与条件

单页与模板是两种结构

普通单页顶层只有布局字段；使用 state、variables、characters、samples、collections、forms 时，应改成下面的 pages 家族模板。文件名匹配家族 id，打开命令使用家族中的 page ID。所有文件的 page ID 不能重复。

wiki-app.yml · 完整示例
schema-version: 1
id: wiki-app
characters: '龘'
state:
  editing: 'false'
variables:
  mode:
    type: state
    source: editing
    fallback: 浏览
    values: {'false': 浏览, 'true': 编辑}
pages:
  wiki-home:
    canvas: {width: 300, height: 180}
    frontend:
      mode:
        type: text
        content: '当前模式：{mode}'
        color: '#243247'
        offset: {y: 40}
      toggle:
        type: text
        content: 切换编辑
        color: '#243247'
        actions: 'toggle: editing'
      hint:
        type: text
        content: 编辑中
        color: '#2563EB'
        offset: {y: -28}
        visible-if: '{editing}'
      close:
        type: text
        content: 关闭
        color: '#243247'
        offset: {y: -64}
        actions: close

执行 /dialogmenu open wiki-home。切换后显示“编辑中”，再次切换隐藏。characters 仅演示额外字形准备，不要求在画面中出现该字。

变量类型

typesource
literal字面字符串，可展开已有变量。
state当前 state 的键名。
papiPlaceholderAPI 表达式，需相应 expansion。
skriptSkript 变量来源，需对应脚本和数据。
externalJava binding 提供的数据键；省略 source 时使用变量名。

通用字段：type / source / fallback / preview / max-length / values。preview 用于准备阶段，fallback 用于缺失数据，values 把离散值映射为显示值。{player} 与 {uuid} 是内置玩家占位。

max-length 不是普通字符串截断变量上的该字段用于受限数字显示：过长数字会进行缩写或科学计数，非数字可能输出 -。不要给玩家名字或任意正文加它来“截字”。表单字段的同名参数则是真正的输入长度限制。

visible-if

仅模板可用，可用于元素和整个组。表达式展开后必须严格为字符串 true 或 false，不是 JavaScript、比较表达式或权限表达式。隐藏的元素不保留点击目标。

samples 与动态几何

模板顶层 samples 是变量名到预览值的对象列表；变量必须先声明。可准备不同颜色、图源和几何变体。几何展开支持 offset 的 x/y/z，以及 width、height、size、line-width 等数值字段。

运行时值必须落在已准备资源的范围内。动态换了一张新图、一个新字号或新颜色，不会自动把所有可能值都预生成。多个变量的组合应显式给出代表性 samples，不假定 values 自动穷举笛卡尔积。

按钮分页

少量固定页面可直接 open；动态列表可由业务端推送外部集合。下面演示最简单、完整且可直接打开的两页，使用不同 page ID，避免把显示文字当状态表达式。

        offset: {y: 30}
      next:
        type: text
        content: 下一页
        color: '#243247'

更复杂的列表

state 可以保存页码，由业务或已准备的映射控制内容；没有自动执行算术表达式的 set: page {page}+1。局部列表、固定页脚或无限数据虚拟化不是原生 flow-list 的能力。

点击翻页可能替换页面身份；不要缓存旧页面点击令牌继续发送。Java binding 只能打开同一 YAML 家族内的页面。

集合与原生表单

插件持有的集合

Java 插件管理动态数据时，使用 external: true。YAML 负责行格式，Java 负责条目和业务操作，不必为每次增加数据修改 YAML。

wiki-catalog.yml · 完整示例，与 Java 示例配套
schema-version: 1
id: wiki-catalog
variables:
  selected:
    type: external
    source: selected-id
    fallback: none
    preview: none
collections:
  entries: {external: true}
forms:
  create:
    title: 新建条目
    submit: 提交
    cancel: 取消
    fields:
      name: {label: 名称, initial: '', max-length: 24}
pages:
  wiki-catalog-list:
    canvas: {width: 300, height: 120}
    frontend:
      title:
        type: text
        content: '选中：{selected}'
        color: '#243247'
        offset: {y: 30}
      create:
        type: text
        content: 新建
        color: '#243247'
        actions: 'callback: create'
      close:
        type: text
        content: 关闭
        color: '#243247'
        offset: {y: -35}
        actions: close
    flow-lists:
      content:
        collection: entries
        title: 条目
        row: '{entry.name} · {entry.size}'
        empty: 暂无条目

使用 binding.updateCollection("entries", rows) 替换数据。条目必须使用唯一稳定 ID，点击返回该 ID，并复核条目当前存在与权限。

flow-lists 的滚动边界

列表作为原生 Dialog 正文追加，使用整个正文的滚动。不是画布中的局部滚动区，没有固定标题/页脚、自定义滚轮监听或无限项虚拟化。条目可以很多，但需要自行控制刷新频率和规模。

占位字段为 {entry.id}、{entry.name}、{entry.image} 和自定义字段。image 是显示数据 token，不会自动生成行内 image 控件。

forms

顶层 forms 声明原生文本输入表单，通过 binding.openForm("create", callback) 打开。字段支持 label、initial、max-length，长度为 1..128，默认 64。

提交回传“字段键 → 输入值”，业务插件仍需校验重名、权限、价格等规则。取消或 Esc 不提交并恢复最新列表；表单打开期间后台数据更新不应覆盖输入。关闭、替换、暂停或重载后过期提交被清理。

Skript 集合与网格

另一条集合路径通过 Skript 的 load/list/status/write/token/result 等字段联动，需自行实现对应协议；不能把这些字段与 external: true 混写，Java binding 也不能绑定 Skript-backed 集合。

模板的 entries 定义 label/image/actions，grids 可按 slots、columns、step-x/step-y、width/height、background、icon/text 参数生成有限格子。它与原生 flow-list 不同，容量最多 64，不是同一个自动滚动系统。没有对应脚本时，优先使用上面的 external API，不复制未知服务器脚本名。

资源包与重载

有 CraftEngine

DialogMenu 将生成的 ZIP 登记为 CE 外部资源。默认 craftengine-auto-reload: true 会请求资源更新；仍需检查 CE 自己的生成、上传与分发结果，并让客户端接收。不要再把同一份生成字体手工复制到 CE 源目录，造成重复定义。

没有 CraftEngine

  1. 修改 YAML 后先执行 /dialogmenu reload，等待新快照准备成功。
  2. 执行 /dialogmenu resources，导出到 plugins/DialogMenu/resourcepack/。
  3. 用服务器既有流程将该目录打包、合并并发布，更新对应的资源包地址/散列。
  4. 让客户端接收新包，再打开菜单。

导出的是当前快照，不会替你重读改过的 YAML；也不会仅凭 resources 命令自动把客户端包换新。

修改偏移还要重建吗

改动预期与操作
只改已准备文字的显示偏移通常复用整字 PNG；仍 reload 让布局生效。JSON、行计划、命中代理或 ZIP 可能变化，不能保证永远不用新包。
同一符合条件的图片改宽高可复用 wrapper PNG；仍有布局、命中和包快照检查。
新增字符、颜色、字号、文字倍率或图源需要准备相应资源，reload 后重新发布并接收更新。
换插件发行版或核心 Shader正常停服换 JAR，并生成、接收匹配包；不是 reloadmenu。

本插件命令为 /dialogmenu reload，不是 /reloadmenu。使用服务器自己的别名时，也不能据此跳过资源变化检查。

准备失败与旧快照

布局、字体和 ZIP 在后台单线程准备；失败保留旧有效快照，未变化资源可复用。命令触发后要等待最终成功/失败结果，而不是把“请求已发出”当作发布成功。

资源包压缩大小不等于显存：客户端还需要解压纹理、构建字体与管理命中。不要只看 ZIP 字节数判断 FPS、内存或所有 Shader 兼容性。

Java API

取得服务

以同版本 RGBA JAR 作为 compileOnly 依赖，并在你的 plugin.yml 声明 depend: [DialogMenu] 或按需要使用 softdepend。所有 API 调用必须在服务器主线程。YAML 先用上一章的 wiki-catalog.yml。

下面的类放在你自己的插件项目中，玩家命令或监听器可以调用 show(player)。回调仅演示数据联动，不执行真实交易或持久化。

WikiCatalog.java · 完整可编译类
import dev.dialogmenu.DialogMenuApi;
import dev.dialogmenu.DialogMenuBinding;
import dev.dialogmenu.DialogMenuEntry;
import java.util.List;
import java.util.Map;
import java.util.UUID;
import org.bukkit.entity.Player;
import org.bukkit.plugin.Plugin;

public final class WikiCatalog {
    private final Plugin owner;
    private DialogMenuBinding binding;

    public WikiCatalog(Plugin owner) {
        this.owner = owner;
    }

    public void show(Player player) {
        DialogMenuApi api = owner.getServer().getServicesManager()
            .load(DialogMenuApi.class);
        if (api == null) throw new IllegalStateException("DialogMenu 未就绪");
        if (binding != null) binding.close();
        binding = api.bind(owner, player, "wiki-catalog-list",
            Map.of("selected-id", "none"),
            selected -> {
                DialogMenuBinding current = binding;
                if (current == null || !current.isActive()) return;
                if (selected.equals("create")) {
                    current.openForm("create", fields -> {
                        String name = fields.get("name").strip();
                        if (name.isEmpty()) return;
                        // 示例替换整个集合；真实业务需校验并持久化。
                        current.updateCollection("entries", List.of(
                            new DialogMenuEntry(UUID.randomUUID().toString(),
                                name, "", Map.of("size", "10x20"))));
                    });
                } else {
                    current.update(Map.of("selected-id", selected));
                    player.sendMessage("选中：" + selected);
                }
            },
            reason -> owner.getLogger().fine("菜单关闭：" + reason));
        if (binding != null) {
            binding.updateCollection("entries", List.of(
                new DialogMenuEntry("sample:one", "示例一", "",
                    Map.of("size", "10x20"))));
        }
    }
}
一个实例只持有一个 binding上例适合演示一个玩家流程。多玩家业务应按 UUID 保存 binding，不能用一个全局字段让玩家互相替换。collection ID 与 callback 值共用回调入口，业务应避免重名，例如不要把条目 ID 命名成 create。

基础 API

hasLayout / layouts / open / close / refresh / currentId / sessionToken / surface。返回值需要检查，离线玩家、无权限或失效布局可能无法打开。token 和 surface 是服务端视图身份，不是客户端已经渲染的确认。

Binding 生命周期

方法用途
update(Map)更新声明的 external 数据。
updateCollection(id, rows)替换 external 集合。
openForm(id, submitted)打开 YAML 声明的原生输入表单。
open(page)只能切换到相同 YAML 家族的页面。
suspend / resume暂停点击，再恢复最新数据，适合另一个输入流程。
close / isActive关闭或查询当前句柄；过期句柄不能操作新会话。

DialogMenuEntry ID 为 1..128 字符，允许字母、数字、:、_、-。自定义字段键为 1..64 字符，仅字母、数字、_、-；不能覆盖保留字段 id/name/image。

关闭事件

DialogMenuClosedEvent 提供 player、menuId、token、reason。原因有 CLOSED / REPLACED / RELOAD / DISABLED / PLAYER_QUIT / WORLD_CHANGED / INVENTORY_OPENED。刷新不等于关闭；不要用同一份旧句柄对后来的新会话清理。

RGBA 原理与开销

颜色不是最终显示颜色

“RGBA 版”是发行名称，不代表四个通道全可自由塞数据。文字颜色载荷使用 RGB；A 保持 255。Shader 只有在 GUI、纹理标记和颜色门控同时满足时才解码，最终从调色表还原可见颜色。

协议速览 · 由引擎生成，不写入 YAML color
文字 RGB = 0xD40000 | (top << 8) | paletteIndex
文字 A   = 255
字形纹理标记 RGB = 0x174783

图片 RGB = 0x800000 | ((width - 1) << 14)
                      | ((height - 1) << 5) | (localY & 31)
width / height = 1..512
localY = -8..8

图片宽和高各需 9 位，行内 Y 分配 5 位，加上识别位装入 24 位 RGB。两个 1..512 不是“1024 个通道”，而是两项各有 512 种取值，共 512×512 种宽高组合。

换行和行内偏移

仍然利用原生正文行组织位置，安全时用真实换行进位，局部再做偏移。为了保留混合图片/文字的全局 z 顺序，行计划并非简单对所有 Y 取模；跨行图层需要时仍使用字体基线锚点。

plain_message 行步长为 9px，但独立控件还有上下留白和控件间距。不能把两个独立正文控件的起点差当成一个字形行高。

为什么点击没有跟着 Shader 丢失

原版 CPU 命中不理解 Shader 对顶点的移动。因此可见字形之外，还生成透明度很低的原生代理字格，文字与图片分别集中到 text_hit_all.json、image_hit_all.json。代理随实际位置和尺寸准备，不恢复独立 backend 区域。

省在哪里，仍花在哪里

  • 整字按字号共享，不因新增一个 Y 偏移重新复制一套汉字 PNG。
  • 同一自有图片的 wrapper 可服务不同宽高，避免逐尺寸复制源纹理。
  • 更多字号、倍率、字符、颜色、不同源图和变体仍会增加资源；fallback 图形路径也有成本。
  • 行计划、原生命中代理、字体 JSON、ZIP 和客户端字体缓存仍然存在。

没有一个脱离布局的“每加偏移固定增加多少 KB”。要比较大小，应使用同样的布局、字符、倍率、合包方式和压缩设置，并同时检查实际显示与点击。

迁移与故障排查

移除旧 backend

新版本拒绝 backend，连 backend: {} 也不接受。把动作、提示和交互权限移到对应的可见 text/image 节点，再删除 backend；不能仅把旧矩形点击区删掉，导致动作丢失。

旧区域覆盖整块按钮而文字较小时，迁移后的点击范围会不同。需要整块命中时，使用带动作的图片元素，不要把 actions 挂在 rectangle 或 group 上。

常见问题

现象检查顺序
菜单不存在看 reload 最终结果、文件名/id、重复 page ID、open 目标。模板打开 page ID 而非家族 id。
乱码、方框或缺字确认接收新包、字符在字库中、模板 characters/preview/samples 充分、原字形确实存在。
位置错乱或编码色可见查 renderer=rgba、匹配包版本，以及其他包是否覆盖核心文字 Shader。
背景能看但边缘点不到确认动作在 image 或 text 自身；文字不会让背景整块可点。
纹理直引报错等比、完整不裁切、无旋转、opacity255；非等比拉伸应使用符合条件的自有图。
PNG 无法加载路径在 images 内，宽高16..256且为16倍数，文件是真 PNG。
超出正文范围实际宽64..512、高≤1024、面积预算、画布倍率，以及逻辑宽高比例。
visible-if 非法必须是 pages 模板，展开后严格 true/false，不写表达式比较。
绑定失败或没有回调主线程、owner 已启用、玩家在线、同家族、external 键名、当前句柄、元素权限和 callback 动作。
单击慢了有 double 分支时等待300ms是手势仲裁，不是资源包卡顿。

报告问题时提供

插件版本与 renderer、服务端/客户端版本、GUI 缩放、文字与画布倍率、最小 YAML 和源图尺寸、reload 最终错误、资源包是否已更新，以及有无其他核心 Shader。显示问题提供截图；点击问题说明准确控件、位置、单/双击和预期动作。不要提交账号、密钥或私有业务数据。

兼容性与测试边界

当前适用范围

本文对应独立 RGBA 0.1.5 源码。实际客户端证据来自 Minecraft 26.3 的软件 Vulkan 路径；硬件 OpenGL、Iris、其他核心 Shader 组合及其他版本仍需分别验证。普通玩家无需 Mod，不代表任意图形兼容层都可无条件使用。

编辑桥与共享协议在源码中，但匹配的编辑客户端单独提供；本 Wiki 不把编辑 Mod 当作随 JAR 安装完成的功能。

开发检查不等于玩家验收

源码构建带布局、资源、渲染、点击令牌、绑定和表单回归。已有实际字体与客户端探针检查，但这些不能替代你的服务端启用生命周期、真实权限、交易和完整客户端组合验收，也不构成显存/FPS 保证。

发布前检查清单

  1. 确认只安装一个 DialogMenu，status 为 rgba，所有布局准备成功。
  2. 接收匹配资源包，打开 hello、image-demo 和实际业务页面。
  3. 在 small/medium/large、textscale 各选项、scale 1/0.75 下核对中文、换行、图片边缘和重叠图层。
  4. 验证文字/图片 hover，边缘点击和外侧不触发，单/双击互斥。
  5. 验证翻页、关闭、重开、权限拒绝、刷新后旧控件失效。
  6. Java 集合验证新增/删除/稳定 ID；表单验证提交、取消、输入期间后台刷新和关闭后过期提交。
  7. 业务插件另测真实数据与事务，不把静态示例成功当作交易通过。
